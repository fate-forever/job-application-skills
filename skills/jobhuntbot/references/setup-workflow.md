# 按当前任务准备资料

普通推荐不要求初始化完整求职系统。此手册只在用户要求搭建或当前任务缺少必要资料时使用；复用已有系统，不能为了试用自动建台账、写线索或打开申请流程。

## 三种起点

- 推荐或比较岗位：读取当前简历、目标和相关投递历史。只询问影响资格或选择的缺项；不收集完整住址、家庭、证件、薪资或签证，除非真实条件需要。
- 持续查公司：明确公司池、结果保存位置、当前资料和最新记录。已有文档或断点继续使用，不为新对话重建。
- 填写网申：明确公司、岗位、简历版本和填写/保存/提交范围，准备已确认事实与缺项。需要可操作浏览器；没有时只准备草稿。

这些模式不互相授予权限。已确认的信息与已有明确授权直接复用，只有新增事实、冲突、目的地或实质变化才补问。当前工具要求动作时确认的仍遵守其规则。

## 第一次设置

1. 先识别现有资料、材料版本与记录入口。没有必要资料时集中问少量问题，同时继续独立工作。
2. 用户要求新建结构化资料时使用技能内 `templates/candidate_profile.template.json`，按 [资料约定](profile-contract.md) 写在用户工作区的私有目录，不写进技能文件。
3. 只在用户需要记录且没有现成台账时采用 `templates/dashboard-template/`。看板可选，不是筛岗或填表前置条件。
4. 材料路由按实际职责选择现有版本；是否定制由当前任务决定，不默认追求批量投递。需要编辑时保留原始源文件；PDF 可用于投递和阅读，但原地精确改写需要合适编辑能力或可编辑源文件。
5. 常见自由文本可存私有答案库。已授权起草时直接起草；引入新个人事实或高影响承诺才需要确认。确认过的措辞在相同题意和范围内复用。

## 首次验证

可以先用少量合成或只读任务确认资料与工具能用。试查真实岗位时，只在用户要求记录的范围内保存线索；不生成投递事件、不填真实表单、不提交。实际申请的首次操作仍应是用户请求的真实任务，不为测试额外创建账号或试投。

一次填写是否可执行，取决于本次所需事实、材料、浏览器能力及授权是否齐全，不取决于有没有完成整套模板。需要用户登录、验证码或缺失材料时，保留已完成模块和交接点；不重问已确认的稳定事实。

## 既有台账

沿用用户的阶段与字段。线索、草稿、已保存申请、已提交、后续测评/面试和终止分别处理。使用 [本地工具](local-tools.md) 预览变更；写入依旧由原系统执行。原系统若已有更细阶段，不替换成模板中的少数英文状态。

监控、通知、邮件联系、持续自动执行与最终提交均依赖对应用户请求；设置求职资料本身不授予这些动作权限。
